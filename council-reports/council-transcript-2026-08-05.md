# Стенограмма совета — правила фабрики презентаций Tumodo

Дата: 2026-08-05. Методика: LLM Council (5 советников → анонимное перекрёстное рецензирование → синтез председателя).

## Исходный запрос пользователя

«Проанализируй структуру и дизайн данных презентаций очень внимательно и заполни разделы» (разделы: Структура презентации, Макеты слайдов, Стиль и дизайн; источник — Figma «Презентации», node 6268-3).

## Сформулированный вопрос совета

Дизайн-технолог проанализировал 62 слайда фирменных презентаций Tumodo в Figma (колоды «Brand platform & positioning» в 2 ревизиях и «Tumodo at a Glance») и написал три черновика правил для фабрики презентаций (автосборка HTML 1920×1080 из markdown). Правильны ли и полны ли эти правила? Цена ошибки высокая: правила — закон для всех будущих сборок.

Материалы: черновики трёх файлов правил, структурная сводка 62 слайдов, токены `colors.json`/`typography.json`, CLAUDE.md.

## Ответы советников

### Контрарианец (= Response C в анонимном раунде)

Фатальный изъян найден, и он не один.

1. **Типографика противоречит токенам.** `typography.json` даёт шкалу 80/60/50/30/25/20/16, а черновик style-guide предписывает 88/90/40/34/31/24px — шести из десяти размеров в токенах нет. Сборщик не сможет выполнить style-guide, не нарушив CLAUDE.md. Вдобавок slide-layouts даёт H1 «~55px», style-guide — 50px: файлы спорят между собой.
2. **Арифметика сетки не сходится.** Поля 120px → контент 1680px, а «3 колонки по 584px с зазором 30px» = 1812px > 1680.
3. **Самопротиворечие про манифест**: «мебель кроме манифестов на весь экран» и тут же «манифест: ярлык и номер есть».
4. **Бейдж боли нарушает colors.json**: токен требует «Soft-заливка + Base-обводка, никогда наоборот», правила — заливку peach-base с белым текстом рядом с синим H1.
5. **Тёмная тема не существует в токенах**, но три dark-макета объявлены рабочими.
6. **Лимиты опровергаются референсом**: «H1: 2–6 слов» бракует эталонные слайды (7–8 слов); «H1 всегда x=120» ломается на pain-слайдах.

Вывод: правила самопротиворечивы и частично невыполнимы — фиксировать нельзя.

### Первопринципник (= Response D)

Не тот вопрос: правила отвечают «как выглядят 62 слайда двух колод», а задача — «как детерминированно превратить произвольный markdown в колоду». Скелет — дуга конкретной brand-колоды, для питча/отчёта — прокрустово ложе. Ядро задачи — контракт «тип контента → макет → слоты с лимитами», его нет; макеты описаны прозой в пикселях наблюдений («x≈612–735») — археология Figma, а не спецификация. Фундаментальная дыра: 20 бутиковых макетов и ни одного универсала «заголовок + буллеты»; нет таблиц, графиков, таймлайна, agenda. Лимиты текста — лучшая часть. Оставить: ритм тем, лимиты, Do/Don't, «делить, а не ужимать», открытые вопросы.

### Экспансионист (= Response A)

Правила хорошие — но из золотой жилы взята только проза. Предложения: (1) машиночитаемый `layout-specs.json` из уже собранных координат → `/check-deck` становится валидатором геометрии; (2) golden-тест — пересобрать «Brand platform» фабрикой и сравнить с Figma; (3) diff двух ревизий как источник анти-паттернов; (4) md-скаффолды контентных формул для каждого макета; (5) реестр node-id по макетам в FIGMA-SOURCES.md; открытые вопросы снимать запросом переменных из Figma, а не откладывать.

### Аутсайдер (= Response E)

Глазами исполнителя без доступа к Figma: правила ссылаются на токены по именам без возможности проверки; dark-тема обязательна, но фон «отсутствует в токенах» — собрать нельзя не нарушив «никаких сырых HEX». Термины без определения: «дуги логотипа», «росчерки», «watermark-глифы», «стеклянный бейдж», «иконка-смайл». Тильды повсюду («y≈220», «~530–750px») — два исполнителя дадут разные слайды. Противоречия: манифест-мебель, позиция H1 с бейджем, 50 vs 55px, «строки или знаки главнее». Опечатка «стат主». Процесс: «скелет адаптируется» без правил адаптации разрешает всё.

### Исполнитель (= Response B)

Правила написаны для движка, которого нет: `templates/html/` фактически пуст (только base.html). Блокеры: (1) нет токена тёмного фона — 3 макета несобираемы; (2) нет ассета волнового паттерна — несобираема ни одна колода (cover/final/statement); (3) размеры вне токенов; (4) пустые mockups/ — 6+ макетов зависят; (5) «рукописное обведение», «стекло», «коллажи» не делаются чистым CSS без ассетов. Для первой сборки оставить 7 макетов, остальное — `[v2]`. Первый шаг: выгрузить паттерн, решить тёмный токен, привести шкалу к typography.json, собрать cover в браузере.

## Перекрёстные рецензии (анонимный раунд: A=Экспансионист, B=Исполнитель, C=Контрарианец, D=Первопринципник, E=Аутсайдер)

- **Рецензент-Первопринципник**: сильнейший — C (фальсификация правил против токенов и исходника); слепое пятно — A (не отвечает «правильны ли», автоматизировал бы ошибки). Все упустили: иерархию источников при конфликте; процесс изменения правил; тест лимитов рендером.
- **Рецензент-Контрарианец**: сильнейший — C; второе — D. Слепое пятно — A («оптимизация до валидации»). Все упустили: правило приоритета источников; политику переполнения; проверку шрифтов в fonts/.
- **Рецензент-Экспансионист**: сильнейший — C; B — сильный второй. Слепое пятно — A (его же golden-тест провалился бы). Все упустили: политику деградации; калибровку лимитов под русский (EN-референс, кириллица длиннее на 15–25%); верность рендера шрифтов/PDF.
- **Рецензент-Аутсайдер**: сильнейший — C; D — второй. Слепое пятно — A (валидатор геометрии поверх несходящейся сетки — автоматизация ошибки). Все упустили: поведение при нарушении входа; приоритет файлов; шрифты и лицензии.
- **Рецензент-Исполнитель**: сильнейший — C; B — второй. Слепое пятно — A. Все упустили: порядок приоритета при конфликте; кириллицу.

## Вердикт председателя

**Согласие совета**: черновики верно схватывают визуальную систему (ритм тем, лимиты, Do/Don't — сохранить), но как закон для автосборки не годятся: расхождение с typography.json, несходящаяся сетка, противоречие про манифест, бейдж против правила токенов, несобираемая dark-тема. Единогласно: сильнейший — Контрарианец, слепое пятно — у Экспансиониста.

**Расхождение**: Первопринципник (грамматика + слот-контракты + универсал) vs Исполнитель (вырезать до 7 макетов и собрать слайд). Решение председателя: сделать и то и другое — слот-контракты компактно в каждый макет, несобираемое пометить `[v2]` с причиной, дугу переквалифицировать из закона в референс + правила выбора для других жанров.

**Пойманное только рецензированием**: иерархия источников (§0), политика переполнения (§5), калибровка лимитов под кириллицу, проверка шрифтов.

**Рекомендация**: переписать все три файла с привязкой каждого стиля к именованному токену; нормировать сетку (540/30, 825/30, 390/40 → ровно 1680); зафиксировать таблицу «мебели»; бейдж боли — по правилу токенов с открытым вопросом; dark-тема и ассето-зависимые макеты — `[v2]`; добавить `title-bullets`; предложения Экспансиониста (layout-specs.json, golden-тест, diff ревизий, скаффолды) — в бэклог этапа 4 после валидации правил.

**Первый шаг**: привести правила к токенам и записать в rules/ (выполнено этой же сессией); следующий физический шаг фабрики — файлы шрифтов в fonts/files/ и решение по dark-токенам, затем cover в браузере.
