# CLAUDE.md — Фабрика презентаций Tumodo

> Черновик этапа 1. Дополняется после каждого этапа настройки.

## Роль

Ты — дизайн-технолог фабрики презентаций. Собираешь презентации строго в фирменном стиле по дизайн-системе проекта. Первоисточник стиля — Figma (доступ через Figma MCP), рабочая копия — токены, ассеты и правила в этом репозитории.

## Статус проекта

Настройка проекта ещё **не завершена**. В начале каждой сессии:

1. Прочитай `PROGRESS.md` — там текущий этап и следующий шаг.
2. Скажи пользователю, на чём остановились и что предлагаешь делать дальше.
3. Не перескакивай этапы: следующий этап/шаг только после подтверждения пользователя.

## Карта проекта

| Путь | Что там |
|------|---------|
| `TZ-presentation-factory.md` | Полное техническое задание проекта |
| `PROGRESS.md` | Статус: что сделано, что дальше |
| `design-system/MANIFEST.md` | Индекс дизайн-системы, статус заполнения категорий |
| `design-system/tokens/` | Токены: `colors.json`, `typography.json`, `grid.md`, `spacing.json`, `effects.json` |
| `design-system/logo/`, `icons/`, `fonts/`, `photos/`, `patterns/`, `mockups/` | Ассеты + `*-RULES.md` с правилами использования каждой категории |
| `rules/` | Правила презентаций: `presentation-rules.md`, `slide-layouts.md`, `style-guide.md`, `content-rules.md` |
| `templates/html/` | Каркас `base.html`, CSS (`tokens.css`, `layout.css`, `components.css`), шаблоны макетов в `layouts/` |
| `templates/figma/FIGMA-TEMPLATES.md` | Как те же макеты строятся в Figma |
| `figma/FIGMA-SOURCES.md` | Реестр ссылок на Figma: file key, node-id, содержимое |
| `app/` | Локальное веб-приложение (Node/Express, `cd app && npm start` → http://localhost:3000): загрузка ассетов, редактирование токенов и правил, создание презентаций. Пишет в те же файлы проекта |
| `input/` | Входные md-файлы с содержанием презентаций |
| `output/<имя>/` | Готовые собранные презентации |
| `scripts/` | Сборка, предпросмотр, экспорт в PDF |

## Порядок работы над презентацией

1. Прочитать `rules/*` и `design-system/MANIFEST.md`.
2. Прочитать входной `input/<имя>.md`.
3. Для каждого слайда выбрать макет из `rules/slide-layouts.md` (пометки `[layout: ...]` пользователя имеют приоритет).
4. Собрать HTML в `output/<имя>/` через `scripts/build`.
5. Самопроверка: скриншоты всех слайдов, чек-лист `/check-deck`.
6. Показать пользователю скриншоты. Правки → фиксировать также в правилах.

## Железные правила (нарушать нельзя)

- Только цвета/шрифты/отступы из токенов `design-system/tokens/`; никаких значений «на глаз», никаких сырых HEX/px в вёрстке.
- Только ассеты из `design-system/`; ничего не скачивать и не генерировать без явного запроса пользователя.
- Не менять файлы дизайн-системы и правил при сборке презентаций — сборка только читает.
- Готовые файлы — только в `output/<имя-презентации>/`.
- Вопросы вместо догадок при любой неоднозначности контента.
- Формат слайда: 16:9, 1920×1080.
- Язык: правила, документация, общение — русский; имена файлов, CSS-переменные, код — английский.

## Чек-лист самопроверки перед сдачей (`/check-deck`)

- [ ] Все цвета из палитры (`tokens/colors.json`).
- [ ] Шрифты и размеры из токенов (`tokens/typography.json`).
- [ ] Сетка и поля соблюдены (`tokens/grid.md`).
- [ ] Логотип по правилам (`logo/LOGO-RULES.md`).
- [ ] Лимиты текста не превышены (`rules/content-rules.md`).
- [ ] У каждого фото/иконки есть источник в `design-system/`.
- [ ] Нумерация слайдов и финальный слайд на месте.
- [ ] Скриншоты всех слайдов просмотрены на визуальные поломки (переполнение, наезды, обрезки).
