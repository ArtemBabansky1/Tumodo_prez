# Правила использования мокапов

Машиночитаемый каталог: `mockups/catalog.json`. В нём хранятся описание, назначение, смысловые теги, допустимые роли слайда, ограничения и Figma source node для каждого файла.

## Категории

- `files/` — базовые сцены и универсальные мокапы: ноутбуки, iPhone, карта мира.
- `screens/` — реальные экраны Tumodo: dashboard, поездка, финансы, отчёты, travel policy и отдельные UI-фрагменты.
- `devices/` — готовые устройства с уже вставленным продуктовым экраном.

## Как выбирать

- Для общего рассказа о платформе использовать `desktop-dashboard-overview` или ноутбук с dashboard.
- Для доказательства конкретной функции выбирать экран по смыслу: поездка → `trip-detail-flight-hotel`, финансы → `finance-invoices`, данные → `reports-travel-analytics`, compliance → `company-travel-policy`.
- Для мобильного опыта использовать один крупный iPhone или один вертикальный экран. Два устройства допустимы только в явном сравнении desktop/mobile.
- Экран должен быть читаемым: продуктовый мокап занимает не меньше трети слайда, а детальный desktop screenshot — обычно половину или больше.
- Browser-proof скриншоты с Safari использовать как доказательство работающего продукта; чистые экраны — для более редакционной и спокойной композиции.

## Чего нельзя

- Подбирать экран только потому, что он фирменного цвета: функция на экране должна подтверждать тезис слайда.
- Накладывать текст или диаграммы поверх интерфейса; текст живёт в отдельной колонке или карточке.
- Смешивать на одном слайде несколько полноценных desktop-экранов без задачи сравнения.
- Выдавать mobile web в Safari за нативное приложение.
- Искажать пропорции устройства или экрана; кроп допустим по системной панели браузера и внешним пустым полям, но не по ключевой функции интерфейса.
