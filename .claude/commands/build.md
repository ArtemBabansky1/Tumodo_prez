argument-hint: <имя>

Собери HTML-презентацию из `input/$ARGUMENTS.md` по правилам проекта.

Алгоритм:
1. Прочитай `CLAUDE.md`, `rules/agent-workflow.md`, остальные `rules/*` и `design-system/MANIFEST.md`.
2. Определи коммуникационную задачу и роль каждого слайда. Сам выбери макет, конкретный canon variant и ассеты.
3. Запиши решения в `input/$ARGUMENTS.md` и `output/$ARGUMENTS/deck-plan.json`.
4. Если контент не помещается — сократи формулировку без потери фактов или раздели слайд по правилам переполнения. Не проси пользователя выбирать дизайн.
5. Собери через `node scripts/build.js $ARGUMENTS` самодостаточный `output/$ARGUMENTS/index.html`.
6. Визуальный цикл (обязателен): `node scripts/screenshot.js $ARGUMENTS` → открой каждый скриншот и выбранный для него canon variant → сверь композицию, отступы, визуальный вес и антипаттерны → исправь → пересними слайд, максимум 3 итерации.
7. Не подменяй нереализованный канон универсальным макетом молча: расширь движок или сделай сохраняемое переопределение слайда вне дизайн-системы.
8. Прогони `/check-deck` и покажи пользователю готовый результат.

Железные правила: только токены и ассеты из `design-system/`; сборка не меняет дизайн-систему и правила; результат только в `output/$ARGUMENTS/`.
