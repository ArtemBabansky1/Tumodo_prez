# Canon — эталонные слайды

Визуальный эталон качества. При сборке Claude сравнивает скриншот каждого собранного
слайда с эталоном соответствующего макета и доводит результат до совпадения по духу:
композиция, визуальный вес, воздух, положение элементов.

## Структура

| Папка | Что класть | Именование |
|-------|-----------|------------|
| `layouts/` | Один каноничный PNG на каждый макет из `templates/html/layouts/` | Точно как файл макета: `cover.png`, `title-bullets.png`, `numbered-cards-3.png`, … |
| `decks/` | Полные эталонные презентации («вот это — 5 из 5»), по подпапке на колоду | `decks/<имя>/slide-01.png`, … |
| `bad/` | Антипримеры: неудачные слайды с кратким описанием, что не так | `bad/<что-плохо>.png` + строка в `rules/mistakes.md` |

## Требования к эталонам

- PNG 1920×1080 (экспорт из Figma в масштабе 1x или скриншот утверждённого слайда).
- Один макет — один главный файл `<layout>.png` (эталон геометрии для калибровки);
  вариации — через суффикс `.var-2`, `.var-3`, … (другая тема, другой состав карточек).
- При сверке слайд сравнивается с главным эталоном; вариации показывают допустимый разброс.
- Эталон обновляется только осознанно: новый файл = новый стандарт качества.
- Актуальное распределение файлов по макетам и его история — в `AUDIT.md`.

## Как это используется

1. `/build` собирает колоду и делает скриншоты (`node scripts/screenshot.js <имя>`).
2. Claude открывает рядом скриншот слайда и эталон его макета из `layouts/`.
3. Расхождения (композиция, отступы, размеры, вес элементов) — правятся, слайд
   переснимается (`node scripts/screenshot.js <имя> <номер>`), снова сверяется.
4. Систематические расхождения фиксируются в шаблоне (`templates/html/`)
   и/или в `rules/mistakes.md` — чтобы ошибка не повторялась.

Пока для макета нет эталона — сверка идёт по `rules/style-guide.md` и полным колодам
из `decks/`. Список макетов без эталона Claude сообщает при каждой сборке.
